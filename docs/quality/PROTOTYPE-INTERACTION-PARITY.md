# 原型交互差距整改 · 2026-09-08

本轮在同一任务中打开 `prototype/index.html` 与真实原生应用，依次操作新任务、输入与确认范围。原型用于交互设计参照，不作为业务执行证据。

| 步骤 | 原生应用发现的问题 | 整改 |
| --- | --- | --- |
| 新任务 | 首屏展开路由、minor units、KPI ID 等十多个工程字段，鼠标点击后也没有聚焦输入 | 先输入目标；按钮和键盘入口同样聚焦，工作台收起 |
| 确认范围 | 创建按钮只显示不可用，没有明确缺少哪项 | 单独确认步骤、业务名称、可修改建议、逐项缺项提示与定位 |
| 调整预算与完成标准 | 预算要求用户填写最小货币单位，指标要求机器 ID | 人类可读的金额、币种与指标；精确转换、溢出和精度检查 |
| 打开模型设置 | 用户不清楚是否会丢失尚未创建的任务 | 返回原确认步骤，保留项目草稿 |
| 切换任务与快捷入口 | 一个输入状态复用于多条任务；Cmd+K 会强制切到总调度 | 草稿绑定精确项目/任务，Cmd+K 保持当前目标 |
| 异步结束 | 发送结束可以清掉已经切换到的输入框 | 只清理原作用域且内容未变的已提交草稿 |
| 创建期间离开 | 创建完成后可能抢走新页面，或留下无法解除的忙碌状态 | 保持当前页面；未进入执行的持久任务可重新打开恢复，释放忙碌状态 |
| 项目重新锁定 | 确认页可能继续显示先前可访问的私有草稿 | 保留内存草稿，立即卸载所有私有确认字段，仅显示解锁提示 |

实现保持既有 Rust Application 创建、Runtime post-render dispatch、审批与回执边界。方向建议是本机可修改默认值，歧义目标不自动选型。新任务最终确认之前不创建持久 Mission，不发送模型请求。

验收应分别记录：目标输入与 IME/键盘、无效范围定位、预算小数、修改目标、设置往返、任务/项目草稿隔离、实际创建与创建失败保留输入。真实原生截图与操作、代码回归和独立审查不得相互替代。

仍存在的产品差距：统一多模型配置、模型自动提出完整任务范围、旧任务通用对话迁移，以及各业务工作面的真实外部执行链路。未发送草稿暂不跨进程持久化。本轮不能据此宣称完整原型已全部实现或完整产品合格。
