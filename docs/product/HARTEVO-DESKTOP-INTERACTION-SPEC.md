# Hartevo Desktop：Growth Operations 交互规格

状态：**Current**
版本：Desktop v12 冻结交互基线
范围：渠道、社媒、邮件与 CRM、达人发现与建联、联盟营销，以及这些业务依赖的外部连接、权限、审批和验证。

## 1. 产品原则

1. 用户始终从自然语言 Mission 开始，不需要先学习或配置工作流。
2. 连接是能力前提，不是产品主任务；当前阶段不需要的连接不阻断 Mission。
3. 连接成功不等于允许执行。读取、发布、触达、邀请、合同、预算和付款分别受策略与审批控制。
4. 公开发现、租户私域、Hartevo Opt-in 与官方网络是不同供给事实，不混写、不虚构。
5. 每次外部动作都保留 Effect、Provider Receipt、Verification 与 Outcome，失败或不确定时冻结并核验。

### 1.1 用户、宣发项目与 Mission

产品层级固定为：**用户 / 组织 → 宣发项目 → Mission → Effect、Receipt 与 Outcome**。

- 用户级：账户、团队成员、默认模型偏好，以及可复用的 Skills、Plugins 和 MCP 能力。
- 宣发项目级：市场与品牌边界、Truth Graph、连接与 Scope、Consent、审批策略、Mission 历史和成果。不同项目默认隔离，不自动共享联系人、私有事实或外部写入权限。
- Mission 级：在当前项目上下文中，由自然语言目标即时编译的任务、计划、执行和验证过程。

左下角常驻当前宣发项目。鼠标移入、点击或聚焦后按 `ArrowUp`，项目切换器向上展开；`Escape`、点击外部或移出后关闭。切换项目时，顶部身份、任务列表、事实数量、连接状态、审批边界、增长运营数据和成果同步切换，并默认进入该项目的总调度。项目首页保留为显式入口，不作为切换后的默认落点。

“新建宣发项目”不要求填写传统配置表。用户先用自然语言说明市场、产品、目标和限制，Hartevo 再建立独立 Truth Graph、Mission 记忆、连接范围、审批策略与成果空间。账户、团队和全局设置仍从用户级入口管理。

### 1.2 唯一总调度会话

Hartevo 每个宣发项目只有一个持续存在的 **总调度会话**。它负责目标理解、Mission 编译、进度说明、方向调整、审批和结果复盘。连接中心、渠道、CRM、达人与联盟是同一 Mission 的结构化工作面，不拥有各自独立的会话，也不要求用户在模块之间手工传递上下文。

- 主入口：左侧“总调度”是持续交互入口。会话区明确展示当前 Mission 正在协调的工作面，以及每个工作面的实时状态。
- 主输入：完整自然语言输入、模型、推理强度与速度只出现在总调度。用户在这里连续描述目标、改变方向、设置停止条件或要求转人工。
- 工作面：进入模块后只展示结构化状态与专业操作，不再重复放置完整输入框。底部共享状态条说明当前工作面属于哪个 Mission、哪些状态已经同步，并提供“回到总调度继续”。
- 上下文回流：模块里的“创建渠道 Mission”“创建建联 Mission”等按钮不会在模块内新开会话，而是携带当前对象、筛选条件和工作面状态返回总调度，预填为下一条指令。
- 自动同步：所有工作面订阅同一份 Mission State、Truth Graph、Effect Ledger 和 Approval Policy。任何进度、连接、回执、失败与人工接管状态都会自动回写，不需要用户刷新或逐个查看。
- 自动回到任务：为某条指令完成必要连接后，产品自动回到原总调度会话并恢复 Mission；用户不需要重新输入目标。
- 快捷入口：在任意工作面按 `Ctrl / Cmd + K` 会回到总调度并聚焦主输入，而不是在当前模块生成另一个输入框。

项目首页的“描述新任务”和各业务工作面的动作按钮都是总调度的上下文入口。它们可以预填指令，但会话、审批、记忆和成果始终归属于同一 Mission Thread。切换宣发项目时，总调度、工作面状态和未提交输入必须一起切换，禁止跨项目静默继承。

## 2. 一级信息架构

### 业务工作面：增长运营

- 渠道运营：渠道选择、内容日历、发布队列、成效与回执。
- 关系与 CRM：Consent、联系人、邮件序列、Inbox、人工接管、商机阶段。
- 达人与联盟：供给网络、达人发现、建联管线、Program、归因、佣金和付款。

### 能力层：系统与连接

- 连接中心：账号、OAuth、Scope、健康状态、重新授权、暂停、活动日志。
- 能力中心：当前 Mission 编译出的最小能力子图。
- Skills / Plugins / MCP：任务能力、产品化插件和工具协议，不与业务对象混在同一导航层。

## 3. 连接中心

### 3.1 总览

- 显示当前 Mission 是否可以继续，以及进入下一阶段前还缺什么。
- 推荐连接按 Mission 价值排序，不要求用户一次连接全部服务。
- 已连接项只有真实 Probe 成功才显示“已验证可用”。
- 过期连接自动暂停相应写入任务，但保留草稿、计划和执行记录。

### 3.2 全部连接

每个连接对象至少包含：

- Provider 与账号身份
- 所属租户、项目和 Workspace
- 已授予 Scope
- 读取/写入能力
- 最近 Probe、速率限制和有效期
- 使用它的 Mission
- 暂停、重连和撤销入口

### 3.3 权限策略

动作按风险分层：

- 自动允许：账号健康检查、当前项目范围内的只读同步。
- 策略允许：满足既定对象、预算、频率和内容边界的重复动作。
- 必须确认：首次发布、首次邮件、批量触达、达人邀请、合同、预算变更、佣金和付款。
- 禁止自动重试：付款、不确定的外部写入、可能重复发送或重复发布的动作。

### 3.4 连接流程

1. 确认用途：说明当前 Mission 为什么需要该连接。
2. 审阅最小权限：读取和外部写入分开展示。
3. 服务商授权：密码不进入 Hartevo；授权绑定用户、项目、用途和有效期。
4. 真实验证：核对账号身份、Scope 与 API Probe 后才变为可用。

## 4. 渠道运营

### 4.1 渠道计划

- 按 Audience Fit、证据、成本、连接状态与品牌风险排序。
- 只突出当前 Mission 相关渠道，避免展示无关的渠道目录。
- 未连接渠道仍可完成研究和草稿，但不能进入发布队列。

### 4.2 内容日历

- 用渠道原生日历表达内容节奏，而不是把所有内容抽象成同一种卡片。
- 内容对象包含：渠道、账号、受众、素材版本、发布时间、审批状态和验证方式。

### 4.3 发布队列

明确区分：

- 草稿
- 等待审批
- 等待连接或重新授权
- Provider 已接收
- 在线已验证
- 失败或状态不确定

### 4.4 效果

- 展示曝光、互动、访问、转化和成本，同时标注数据来源与时效。
- 未完成独立验证时不宣称因果结果。
- 可从异常指标直接创建新的自然语言 Mission。

## 5. 关系与 CRM

### 5.1 统一生命周期

`identified → permission_unknown → opted_in / legitimate_interest_reviewed → contacted → replied → qualified → opportunity → won / lost / nurture`

### 5.2 Pipeline

- 关系阶段、Consent、来源、负责人和最近动作同屏可见。
- Contact、Company、Opportunity 与 Conversation 是关联对象，不重复造多条真相链。

### 5.3 Inbox

- 邮件、Chatwoot、社媒私信统一进入关系对象。
- 明确显示 Provider 回执和是否为真实入站回复。
- “人工接管”是显式状态；接管后 Agent 停止对该线程自动回复。

### 5.4 邮件序列

- 发送前验证域名、SPF/DKIM/DMARC、Consent、退订、Bounce 和频率限制。
- 公开邮箱不自动等于 Consent。
- 首次发送、批量触达和高风险内容必须确认。

### 5.5 联系人

- 来源、Consent、关系阶段、沟通历史和 CRM 同步状态分别保存。
- 删除或撤回许可后，后续序列自动停止并保留审计记录。

## 6. 达人与联盟

### 6.1 四类供给

- `official_authorized`：Awin、impact.com、CJ 等由租户真实授权的官方网络。
- `hartevo_verified_opt_in`：身份、所有权、联系方式和合作意愿均已验证。
- `tenant_private_import`：租户自己的历史关系，仅属于当前租户。
- `public_discovered_candidate`：公开搜索候选，只能研究，不能宣传为已连接或直接动员。

### 6.2 达人发现

- 展示 Audience Fit、内容相关性、市场、真实性、品牌安全与联系方式许可。
- 公开数字和主页用于发现与评分，不生成虚假的可联系状态。
- 进入详情抽屉后可以查看判断依据、数据时效和下一项允许动作。

### 6.3 建联管线

标准流程：

`发现/导入 → 去重 → 来源与权限验证 → 评分 → 合格 → 审批 → 邀请/申请/谈判 → 条款 → Link/Coupon/Brief/Sample → 激活 → 发布验证 → 归因 → 佣金 → 付款审批 → 培育`

- `permission_unknown` 候选停留在研究区。
- 可建联对象才允许生成 Outreach Pack。
- 每次外发都保留对象、模板版本、审批和 Provider Receipt。

### 6.4 Partner Program

- 管理市场、商品、佣金模型、Cookie Window、退款规则、币种、条款、素材和终止条件。
- Program、Partner、Link/Coupon、Order/Action、Commission、Payout 保持可追溯关系。

### 6.5 归因与佣金

- 订单、退款、币种和归因窗口独立复算。
- 付款审批只创建精确金额的 Payout Effect；Provider 完成后再次验证。
- 不确定付款禁止自动重试，进入人工复核。

## 7. 跨模块交互闭环

### 从自然语言 Mission 开始

1. 用户描述目标与约束。
2. Hartevo 编译 Mission、能力边界与审批边界。
3. 研究阶段仅使用已具备的只读能力。
4. 进入投放、触达或联盟执行前，在任务线程内给出上下文连接建议。
5. 用户完成连接后回到原 Mission，不丢失上下文。

### 从渠道进入关系

1. 内容或广告产生真实回复/线索。
2. Provider 回执进入 Inbox，并关联到 Contact。
3. Consent 与来源被记录后才进入邮件或 CRM 阶段。
4. 高意向对象转为 Opportunity；人工可随时接管。

### 从达人发现进入联盟执行

1. 候选进入供给分类与真实性检查。
2. 满足联系许可后进入建联管线。
3. 条款确认后生成 Program 关系、Link/Coupon 和 Brief。
4. 发布验证、归因、佣金和付款沿同一关系链回流。

## 8. 已覆盖的原型状态

- 唯一总调度入口、共享 Mission Thread 与四工作面实时状态
- 工作面动作携带上下文返回总调度，不创建割裂会话
- 必要连接完成后自动恢复原 Mission
- 连接中心总览、全部连接、权限策略、活动日志
- 四步连接与 Probe 验证流程
- 任务线程内的按需连接建议
- 渠道计划、内容日历、发布队列、效果
- CRM Pipeline、Inbox、邮件序列、联系人
- 达人供给网络、发现、详情、建联管线、Program、归因与佣金
- 详情抽屉、审批、重新授权、人工接管与完成回执
- 1600×1000 与 1366×900 桌面宽度

原型入口：`index.html`

## 9. 任务与总调度信息架构

### 三个层级

1. **宣发项目**：隔离市场、品牌、Truth Graph、连接、审批策略和长期记忆。
2. **持久任务（Mission）**：拥有自己的目标、持续会话、运行状态、审批点与产物，不等同于一次问答。
3. **任务工作台（Workpad）**：报告、计划、结果和能力说明等产物的临时查看区，不是固定第三导航栏。

### 项目总调度

- 总调度是项目级多任务协调视图，不再复用任何一个任务的线程。
- 同时展示进行中、等待用户、自动运行和共享事实摘要。
- 用户可用自然语言创建任务、重排优先级、暂停执行或询问整体进展。
- 各工作面变化自动路由到相关任务，并汇总回总调度；用户无需逐模块巡检。

### 单任务视图

- 点击任务后进入该任务的持续会话，默认使用完整主窗口宽度。
- 输入框仅调整当前任务的目标、范围、优先级或停止条件。
- 任务切换不会改变项目级 Truth Graph，但会切换任务局部状态和产物上下文。

### Workpad

- 默认关闭；点击任务产物或“工作台”按钮后展开。
- 支持多个产物标签、标签切换、单标签关闭、全部关闭和整栏收起。
- 切换 Workpad 标签不会切换任务会话，也不会把“报告/计划/结果”伪装成全局产品导航。
- 关闭 Workpad 后任务会话自动恢复全宽，任务继续运行。

## 10. 用户级入口、跨项目通知与默认落点

### 左上角用户级入口

- Hartevo 品牌栏常驻“全局搜索”和“通知”两个用户级入口，不依赖当前宣发项目。
- 全局搜索覆盖所有项目及其持久 Mission；命中项目时进入该项目总调度，命中具体 Mission 时允许直接深链。
- 原侧栏搜索与 `Ctrl / Cmd + P` 复用同一个全局搜索层，不形成第二套搜索状态。

### 跨项目通知中心

- 通知中心聚合所有项目的“需要你处理”“运行动态”和“完成/异常”事件。
- 每条通知必须显示来源项目、关联任务、事件类型、时间和未读状态。
- 点击具体通知是显式深链：先切换项目上下文，再进入相关 Mission；没有具体 Mission 的项目级事件进入总调度。
- “全部已读”只改变用户级阅读状态，不影响任务运行或审批状态。

### 项目切换语义

- 从侧栏底部切换宣发项目后，默认落到该项目“总调度”。顶栏只保留用户级搜索与通知，不再放置重复的项目切换控制。
- 切换项目同步切换 Truth Graph、连接、审批策略、任务队列与长期记忆，但不会自动打开某个单任务。
- 新建项目完成后同样落到新项目总调度，让用户继续用自然语言分派第一项任务。

### 顶栏空间规则

- 删除网页中伪装的最小化、最大化、关闭控件，避免与真实桌面窗口框架重复。
- 未打开 Workpad 时，任务/总调度顶栏占满可用宽度。
- 只有 Workpad 实际展开时才显示产物标题区；收起后立即归还给主会话。

## 11. 项目与任务编辑

### 对象原位操作

- 项目编辑入口位于项目切换器中的对应项目行，悬停或键盘聚焦时显示。
- 任务编辑入口位于侧栏持久任务行；进入单任务后，顶栏编辑按钮指向当前 Mission。
- 总调度、项目首页和业务工作面中的顶栏编辑按钮指向当前项目，不产生语义混淆。
- 编辑沿用现有右侧对象抽屉，不建立独立设置导航，也不创建新的任务会话。

### 编辑项目

- 可修改项目名称、目标与经营范围、市场与语言、经营对象、默认外部动作策略及事实记忆边界。
- 修改项目名称会同步项目切换器、总调度、通知来源与自然语言入口的项目上下文。
- 既有 Mission、Connections、联系人、Consent、私有事实与 Provider Receipt 不因普通项目编辑而迁移或重写。
- 需要迁移归属、合并项目或归档时，必须进入单独的高风险操作流程。

### 编辑任务

- 可修改 Mission 名称、目标与持续指令、优先级、运行方式和任务审批边界。
- 编辑修改同一个持久 Mission，各工作面自动读取更新后的任务状态，不生成新会话。
- 新设置从下一执行步骤开始生效；已生成的证据、工作产物和外部执行回执继续保留。
- 项目级审批边界仍是上限，任务编辑不能自行扩大项目未授权的外部能力。

## 12. 对象操作菜单与生命周期

### 统一入口

- 项目切换器中的项目行、侧栏任务行与当前对象顶栏均使用三点菜单进入完整操作面；编辑只是其中一项，不再被误解为对象的唯一管理能力。
- 菜单采用固定定位的浮层，不受项目切换器、侧栏滚动区或 Workpad 裁切；鼠标悬停与键盘聚焦均可发现入口。
- 顶栏的快捷置顶按钮随当前对象切换语义：总调度与业务工作面操作项目，单任务视图操作当前 Mission。

### 项目操作

- 支持置顶/取消置顶、打开项目总调度、在项目中新建任务、复制为新宣发项目、编辑、归档/恢复和移除。
- “打开项目总调度”是 Hartevo 对 Codex“在资源管理器中打开”的领域适配；“复制为新宣发项目”承担基于现有上下文建立独立经营单元的需求。
- 复制项目保留可复用的目标、任务模板与事实结构，但新项目的连接授权从零开始，不继承原项目的外部写入权限。
- 归档是可恢复操作：项目仍可在项目管理入口中找到；归档期间不再进入主动调度。
- 移除项目必须输入完整项目名称确认，且至少保留一个用户级宣发项目。移除不会删除外部平台上的账号、内容或已发生动作。

### 任务操作

- 支持置顶/取消置顶、打开任务与连续会话、复制任务链接、复制为新任务、编辑、暂停/恢复、归档/恢复和删除。
- 暂停只停止后续调度，完整保留任务会话、证据、工作产物、审批点和外部回执；恢复后从现有状态继续。
- 归档任务从活跃总调度中移出，并在侧栏归档区保留恢复入口，不把归档伪装成删除。
- 复制任务生成新的 Mission 标识与独立后续状态；原任务继续按既有状态运行。
- 删除任务必须输入完整任务名称确认。删除只移除 Hartevo 中的 Mission，不反向撤销已发布内容、已发送邮件、已支出预算或其他外部副作用。

### 状态同步

- 置顶、暂停、归档、复制和删除后，侧栏任务列表、项目总调度、顶栏当前对象、计数和自然语言上下文在同一次状态提交中刷新。
- 菜单标签必须反映对象的当前状态，例如“恢复任务运行”“恢复已归档任务”“取消置顶项目”，避免用户根据旧状态重复操作。
- 任务深链包含项目与 Mission 索引，打开后加载同一项目 Truth Graph 与任务连续会话，而不是创建一段新对话。

## 13. 本地优先项目、账户与系统设置

### 新建项目的存储决策

- 新建宣发项目必须明确选择存储方式，默认推荐“使用已有本地文件夹”，不能把项目隐式创建成云端容器。
- 支持已有本地文件夹、新建本地文件夹、本地工作副本加密同步、云端工作区四种模式；本地与同步是两个独立决策。
- 本地文件夹选择调用桌面系统目录选择器。创建前显示完整路径、访问边界和是否同步；项目创建后仍可在项目编辑与“数据与存储”中查看。
- 更换项目文件夹先暂停任务、校验完整性并请求确认，不允许后台静默移动。项目文件、OAuth 凭据和可重建缓存必须分别说明保存位置。
- OAuth refresh token、API key 与系统密钥只进入操作系统安全存储，不写入项目目录，也不进入普通同步包。

### 用户账户与离线身份

- 顶部品牌栏只保留 Hartevo、用户级搜索与通知。账户入口归入侧栏底部的用户/宣发项目切换器，位于用户身份行右侧的设置按钮，避免把用户头像塞进全局顶栏。
- 项目切换器不再增加二级账户菜单。底部保留“新建宣发项目”“使用情况与额度”“退出登录”，用户级高频动作直接可达。
- 用户身份行右侧的齿轮直接进入全屏设置，不经过中间浮层；账户、团队、邀请与其他低频管理统一收进设置。
- 退出登录不会删除本地项目。云同步、团队项目和远程 Worker 暂停；登录页明确提供“继续使用本地项目”。
- 离线模式保留本地项目、任务历史与工作成果，并在项目切换器身份行显示明确的离线状态；需要云能力时使用底部的登录入口重新登录。
- 登录只恢复身份和同步，不等于授予项目连接、外部写入、发布、触达、支出或付款权限。

### 完整设置中心

- 设置是用户级全屏系统空间，不塞进项目抽屉。入口来自项目切换器身份行的齿轮和 `Ctrl / Cmd + ,`。
- 设置导航至少覆盖常规、外观与语言、模型与运行、数据与存储、隐私与权限、通知、连接与凭据、账户与团队、用量与计费和快捷键。
- “数据与存储”逐项目展示名称、完整本地路径或云端标识、同步模式、占用与管理动作；本地项目不计云存储。
- “隐私与权限”分别展示文件系统边界、网络访问、外部写入确认和操作系统凭据保护状态，避免用一个“完全访问”开关掩盖不同风险。
- 模型、推理强度和速度在设置中定义默认值，并继续允许在常驻自然语言入口针对当前指令临时调整。
